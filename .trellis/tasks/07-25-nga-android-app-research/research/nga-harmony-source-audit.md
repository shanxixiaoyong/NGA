# Research: nga_harmony source-level API, auth, content, pagination, and posting audit

- Query: Inspect `apap6628114/nga_harmony` at source level, focusing on `NgaClient`, `AuthApi`, `ThreadApi`, `FavoriteApi`, encoding, failover/throttling, credential persistence/logging, BBCode/content safety, pagination, and posting/attachments; distinguish implementation from README/wiki claims.
- Scope: internal
- Date: 2026-07-25

## Findings

### Source snapshot and documentation claims

- Audited local snapshot `references/nga-clients/nga_harmony`, branch ref `main` at `8558a15e5a04c12bf6207265ac33493691aa605e`. The corresponding files under `/tmp/nga-userref-harmony` are byte-identical for `README.md` and `NgaClient.ets`.
- The README claims complete core coverage, favorite-board sorting, complete NGA BBCode, automatic HTML fallback, encrypted/password and Web login, attachment upload, multi-domain automatic failover, and request throttling (`README.md:29-34`, `README.md:39-55`, `README.md:86-91`). Several of these exist only partially, as detailed below.
- Runtime target is HarmonyOS 6.1.0 / API 23 (`build-profile.json5:18-35`); app metadata is still placeholder-like (`AppScope/app.json5:1-9`). GPL-2.0 is present (`LICENSE:1-7`, `README.md:164-166`).

### NgaClient: implemented transport behavior and limitations

- The primary JSON/HTML client is real: three HTTPS NGA domains are configured, JSON requests inject `__inchst=UTF8`, decode every text response as GB18030, identify HTML error pages, sanitize non-standard JSON, and return a parse-error object instead of throwing (`entry/src/main/ets/service/NgaClient.ets:47-55`, `entry/src/main/ets/service/NgaClient.ets:353-401`).
- Main requests are throttled per hostname with a six-request concurrency ceiling and 150 ms minimum dispatch spacing (`entry/src/main/ets/common/concurrency/Throttler.ets:26-43`, `entry/src/main/ets/common/concurrency/Throttler.ets:94-130`). Despite the wiki calling it a token bucket, there is no token/refill state; it is a semaphore plus dispatch-spacing queue.
- Failover happens only when the Harmony HTTP call rejects. `httpReq` resolves all HTTP status codes, and `executeWithRetry` never classifies 4xx/5xx or bad bodies as transport failure (`entry/src/main/ets/service/NgaClient.ets:133-165`, `entry/src/main/ets/service/NgaClient.ets:249-279`). Thus a reachable WAF/challenge/500 response will not try another domain at this layer.
- A successful retry does not update `activeDomainIndex`; the next request starts from the original domain again (`entry/src/main/ets/service/NgaClient.ets:258-281`, `entry/src/main/ets/service/NgaClient.ets:588-603`). `rotateDomain` is defined but has no source caller. `setDomain` exists, but source search found no caller; the persisted `domainIndex` is not applied to `NgaClient` (`entry/src/main/ets/service/api/MiscApi.ets:8-30`, `entry/src/main/ets/store/settings/domain/DisplaySettings.ets:29-32`, `entry/src/main/ets/store/settings/domain/DisplaySettings.ets:51-60`). The README's broad “domain switch / automatic failover” wording is therefore overstated.
- HTML requests deliberately pin the current domain, and their retry loop repeats the same host rather than failing over (`entry/src/main/ets/service/NgaClient.ets:328-337`, `entry/src/main/ets/service/NgaClient.ets:258-275`). Password login is likewise pinned to `https://bbs.nga.cn`; retries repeat that endpoint (`entry/src/main/ets/service/NgaClient.ets:494-540`).
- Captcha/raw requests bypass both throttling and failover (`entry/src/main/ets/service/NgaClient.ets:404-420`, `entry/src/main/ets/service/NgaClient.ets:484-491`). Binary attachment upload also bypasses the shared throttler/failover and uses a hard-coded host (`entry/src/main/ets/service/NgaClient.ets:613-705`). Hence “request throttling” is not comprehensive.
- `withTimeout` is only `Promise.race`; it does not cancel the queued or active request and does not clear its timer (`entry/src/main/ets/common/utils/TimeoutUtils.ets:1-9`). Timed-out pagination/prefetch calls can continue consuming throttler/network capacity in the background.
- Verbose mode logs complete URLs plus full request/response bodies in public log fields (`entry/src/main/ets/service/NgaClient.ets:110-138`, `entry/src/main/ets/service/NgaClient.ets:367-370`). It is off by default, but enabling it exposes post bodies, private API responses, auth/upload fields, and potentially personal content (`entry/src/main/ets/common/utils/Logger.ets:10-19`, `entry/src/main/ets/common/utils/Logger.ets:171-187`).

### Encoding and protocol compatibility

- Posting fields named by the caller are percent-encoded as GBK; surrogate-pair emoji become numeric entities first (`entry/src/main/ets/common/utils/CodecUtils.ets:48-98`, `entry/src/main/ets/common/utils/CodecUtils.ets:100-125`). This preserves basic emoji but not necessarily ZWJ/variation-selector sequences or other BMP characters absent from GBK.
- The generic text multipart builder interpolates names/values without escaping and uses a `Math.random` boundary (`entry/src/main/ets/common/utils/CodecUtils.ets:127-145`). Generic multipart requests still compute `Content-Length` from UTF-16 string length, so non-ASCII values can undercount bytes (`entry/src/main/ets/service/NgaClient.ets:186-190`, `entry/src/main/ets/service/NgaClient.ets:236-242`, `entry/src/main/ets/service/NgaClient.ets:313-320`). Password login explicitly skips that header, but the general `postMultipart` path does not.
- URL building correctly percent-encodes query values (`entry/src/main/ets/common/utils/UrlUtils.ets:27-43`). Link routing later does not `decodeURIComponent`, splits only `key=value` pairs with exactly one `=`, and is case-sensitive about stored schemes, causing compatibility gaps for encoded values and some valid links (`entry/src/main/ets/common/utils/LinkUtils.ets:68-87`, `entry/src/main/ets/common/utils/LinkUtils.ets:124-210`).

### AuthApi and credential security

- Password login really uses the embedded NGA RSA-2048 key and `RSA2048|PKCS1`, then submits a multipart login request over HTTPS (`entry/src/main/ets/service/NgaClient.ets:38-45`, `entry/src/main/ets/service/NgaClient.ets:66-105`, `entry/src/main/ets/service/NgaClient.ets:494-540`). This is server-compatibility behavior, not a replacement for TLS; there is no certificate pinning in the client source.
- Two-step login keeps the plaintext username and password in a module-global map. Entries are deleted only after successful login; expired or failed sessions are not swept and retain the password in memory (`entry/src/main/ets/service/api/AuthApi.ets:17-25`, `entry/src/main/ets/service/api/AuthApi.ets:42-54`, `entry/src/main/ets/service/api/AuthApi.ets:68-95`). Login tokens use `Math.random`, not a cryptographic RNG (`entry/src/main/ets/service/api/AuthApi.ets:179-189`).
- `injectCredentials` does not actually reject invalid uid/cid pairs. Its profile lookup catches every failure and returns `null`, after which it still creates a local session and reports success (`entry/src/main/ets/service/api/AuthApi.ets:159-176`, `entry/src/main/ets/service/api/AuthApi.ets:216-244`). This weakens encrypted credential import and Web login, both of which rely on `injectCredentials` as “validation.”
- Web login enables JavaScript and trusts any console message containing `loginSuccess` plus attacker-controlled JSON, without checking the current origin; it then passes those values to the non-validating injection path (`entry/src/main/ets/pages/LoginPage.ets:183-222`, `entry/src/main/ets/pages/LoginPage.ets:455-469`). The same WebView has no navigation-origin interceptor. Cookie polling executes `document.cookie` on whatever page is current (`entry/src/main/ets/pages/LoginPage.ets:396-445`).
- Local session capability tokens are 64 hex characters generated with `Math.random` (`entry/src/main/ets/store/AuthStore.ets:145-150`, `entry/src/main/ets/store/AuthStore.ets:189-196`). The token, uid, and nickname are persisted in `auth`; uid/cid session records are persisted as plain JSON in Harmony Preferences (`entry/src/main/ets/store/AuthStore.ets:82-104`, `entry/src/main/ets/store/AuthStore.ets:109-150`, `entry/src/main/ets/common/infra/PreferencesStore.ets:42-64`). This is sandboxed storage, but it is not encrypted-at-rest/keystore-backed.
- Backup is globally enabled with no include/exclude rules (`entry/src/main/resources/base/profile/backup_config.json:1-3`), while the backup callbacks are only logging skeletons (`entry/src/main/ets/entrybackupability/EntryBackupAbility.ets:1-15`). Whether Preferences are automatically included is platform-dependent and needs a device-level test; the source provides no explicit credential exclusion.
- Exported `.ngacred` files are materially better protected: PBKDF2-SHA256 (120,000 iterations), random salt/IV, and AES-256-GCM are implemented (`entry/src/main/ets/common/security/CredentialExportCrypto.ets:5-12`, `entry/src/main/ets/common/security/CredentialExportCrypto.ets:80-105`). Import does not bound file size, decoded field sizes, or the attacker-supplied iteration count before KDF execution (`entry/src/main/ets/pages/LoginPage.ets:294-345`, `entry/src/main/ets/common/security/CredentialExportCrypto.ets:107-133`), leaving memory/CPU denial-of-service risk from a malicious file.
- NGA cookies injected into the general WebView omit `Secure`, `HttpOnly`, and `SameSite` attributes (`entry/src/main/ets/pages/WebViewPanel.ets:62-76`). They are host-scoped but can potentially be sent on HTTP navigation to the same host; this needs device/WebCookieManager verification.
- The checked-in build profile contains developer machine paths and password-looking signing material, while release obfuscation is disabled (`build-profile.json5:3-15`, `entry/build-profile.json5:11-23`). The referenced key files are not present, and DevEco may encode these values, but they should still be treated as leaked build metadata pending confirmation.

### ThreadApi and HTML fallback

- JSON-first thread retrieval with taskpool HTML fallback is genuinely implemented (`entry/src/main/ets/service/api/ThreadApi.ets:40-119`). The shared mapper builds posts, nested comments, attachment records, thread metadata, and pagination (`entry/src/main/ets/service/api/ThreadApi.ets:151-278`).
- Reading requires a valid local app session even for publicly readable threads (`entry/src/main/ets/service/api/ThreadApi.ets:45-50`). A pid-only request is accepted by validation but the forced HTML branch sends only `tid` and `page`, dropping `pid`, so pid-only deep-link retrieval is broken (`entry/src/main/ets/service/api/ThreadApi.ets:54-67`).
- The forced `getThreadHtml` path and force-HTML branch mark the result successful through `fillThreadResult` even when parsing yields zero posts; only the JSON-fallback branch adds an explicit empty-post failure check (`entry/src/main/ets/service/api/ThreadApi.ets:60-70`, `entry/src/main/ets/service/api/ThreadApi.ets:99-113`, `entry/src/main/ets/service/api/ThreadApi.ets:284-313`). Challenge/error HTML can therefore become an apparently successful empty result in forced mode.
- `getPostAuth` does not call `parseNgaError` and sets `ok=true` even when `auth` is absent or the server returned a business error (`entry/src/main/ets/service/api/ThreadApi.ets:318-346`). Reply/comment submission does parse NGA errors and GBK-encodes content (`entry/src/main/ets/service/api/ThreadApi.ets:349-428`).

### FavoriteApi and the claimed favorite-board sorting

- Topic voting and check-in parse NGA business errors (`entry/src/main/ets/service/api/FavoriteApi.ets:53-85`, `entry/src/main/ets/service/api/FavoriteApi.ets:140-160`). In contrast, forum-favorite fetch does not parse an error object, while topic add/remove favorite ignore the response entirely and report success if the HTTP promise resolves (`entry/src/main/ets/service/api/FavoriteApi.ets:14-48`, `entry/src/main/ets/service/api/FavoriteApi.ets:90-135`). Because transport does not reject 4xx/5xx, UI state can claim a favorite mutation succeeded when the server rejected it.
- Favorite boards are fetched from the server, but UI star toggles only mutate the local settings array; there is no server-side add/remove board API call (`entry/src/main/ets/store/settings/domain/SocialListSettings.ets:59-105`, `entry/src/main/ets/pages/CommunityPanel.ets:140-156`). A delayed server refresh replaces the entire local array and order when non-empty (`entry/src/main/ets/store/settings/domain/SocialListSettings.ets:61-90`).
- The README's “supports favorite sorting” claim is not implemented. `FavBoard` has only `fid/stid/name`, Settings exposes only add/remove, and all favorite UIs are plain `ForEach` lists/grids with click handlers—no long-press, drag, reorder method, or persisted order operation (`entry/src/main/ets/model/SocialEntries.ets:7-15`, `entry/src/main/ets/store/SettingsStore.ets:139-143`, `entry/src/main/ets/pages/CommunityPanel.ets:429-465`, `entry/src/main/ets/pages/CommunityPanel.ets:539-578`). Repository-wide source search found no favorite reorder/drag implementation.

### BBCode implementation and content-safety boundaries

- BBCode is parsed into a native AST and rendered as ArkUI components rather than injected HTML, which materially reduces classic script/XSS risk. The AST covers 39 enum values and the renderer handles many common NGA constructs, including links, images, nested quotes, collapse blocks, code, lists, media, warning blocks, albums, alignment, and tables (`entry/src/main/ets/model/BBCodeNode.ets:1-59`, `entry/src/main/ets/common/components/BBCodeContentView.ets:267-450`).
- Link URLs reject `javascript:`, `vbscript:`, and `data:` and allow HTTP(S), mailto, and some relative NGA forms (`entry/src/main/ets/parser/bbcode/lexer.ets:51-62`, `entry/src/main/ets/parser/bbcode/inline-parser.ets:173-203`). However, the click router handles only internal hashes and HTTP(S); allowed `mailto:` and relative links are silently inert (`entry/src/main/ets/common/utils/LinkUtils.ets:124-210`).
- Images do not pass through `isSafeUrl`. `resolveImgUrl` returns arbitrary absolute/raw schemes and arbitrary hosts, and the renderer passes them directly to `Image` (`entry/src/main/ets/parser/_shared/AttachUrl.ets:36-44`, `entry/src/main/ets/parser/bbcode/block-handlers/handleImg.ets:36-51`, `entry/src/main/ets/common/components/BBCodeContentView.ets:453-531`). This permits remote tracking and potentially local/custom URI probes depending on ArkUI's accepted schemes; constrain schemes/hosts in an Android port.
- Parser/render limits are absent: quote/collapse/list/table handlers recurse without maximum depth, font size percentages are unbounded above, and table spans are not capped (`entry/src/main/ets/parser/bbcode/parser.ets:30-103`, `entry/src/main/ets/parser/bbcode/block-handlers/handleQuote.ets:14-50`, `entry/src/main/ets/parser/bbcode/inline-parser.ets:230-275`, `entry/src/main/ets/common/components/bbcode/bbcode-utils.ets:23-32`). Adversarial or pathological posts can cause stack, allocation, or layout denial of service.
- “Complete BBCode” is overstated. `FLASH` is only a clickable placeholder, dice content is discarded, style attributes are parsed then ignored, and table `rowSpan/colWidth` are parsed but only `colSpan` affects rendering (`entry/src/main/ets/parser/bbcode/block-handlers/handleFlash.ets:49-70`, `entry/src/main/ets/parser/bbcode/block-handlers/handleFormat.ets:9-20`, `entry/src/main/ets/parser/bbcode/block-handlers/handleFormat.ets:98-116`, `entry/src/main/ets/common/components/BBCodeContentView.ets:420-447`, `entry/src/main/ets/common/components/BBCodeContentView.ets:771-807`). `HR` and `PARAGRAPH` exist in the enum but have no parser/renderer branch (`entry/src/main/ets/model/BBCodeNode.ets:35-39`).
- Fidelity bugs include `decodeHtmlEntities` stripping any residual `<...>` text, and code/collapse/album titles escaping angle brackets into literal `&lt;`/`&gt;` strings before native `Text` rendering (`entry/src/main/ets/parser/_shared/HtmlEntityCodec.ets:63-72`, `entry/src/main/ets/parser/bbcode/block-handlers/handleCode.ets:14-27`, `entry/src/main/ets/parser/bbcode/block-handlers/handleCollapse.ets:15-26`, `entry/src/main/ets/common/components/BBCodeContentView.ets:600-668`).
- Collapse expanded state is keyed only by title, so multiple collapse blocks sharing a title toggle together (`entry/src/main/ets/common/components/BBCodeContentView.ets:600-649`).

### Pagination: real implementation plus edge cases

- Topic and thread pagination are substantive: generation counters discard stale responses, prefetch maps hold look-ahead pages, topic append deduplicates by `tid`, and thread append/prepend deduplicates by floor number while tracking page-per-index (`entry/src/main/ets/common/managers/PaginationManager.ets:16-112`, `entry/src/main/ets/common/managers/TopicPaginationManager.ets:41-100`, `entry/src/main/ets/common/managers/ThreadPaginationManager.ets:55-203`). Thread UI supports seamless append/prepend and traditional page selection (`entry/src/main/ets/pages/ThreadPanel.ets:208-317`, `entry/src/main/ets/pages/ThreadPanel.ets:320-460`).
- Prefetched empty pages are consumed without advancing `currentPage`: both commit methods delete an empty holder and return before `applyState`. With blacklist/keyword filtering, a server page can become empty, causing repeated attempts at the same next page (`entry/src/main/ets/common/managers/TopicPaginationManager.ets:92-100`, `entry/src/main/ets/common/managers/ThreadPaginationManager.ets:166-179`, `entry/src/main/ets/pages/TopicListPanel.ets:325-336`, `entry/src/main/ets/pages/ThreadPanel.ets:432-444`).
- Filtering removes keyword-matched top-level rows but retains server total-row/page counts, making empty filtered pages more likely (`entry/src/main/ets/parser/ThreadParser.ets:12-37`).
- After a reply on the last page, the page reloads page 1, not the last/returned pid page (`entry/src/main/ets/pages/ThreadPanel.ets:464-475`). The wiki describes this as reply-position handling, but it does not actually navigate to the newly returned `pid` (`.wiki/页面模块/主题列表与帖子详情.md:284-287`).

### Posting and attachments

- Reply, floor quote, comment, edit, anonymous flag, drafts, BBCode toolbar, emoticons, and repeated image uploads are implemented (`entry/src/main/ets/common/managers/ReplyManager.ets:11-243`, `entry/src/main/ets/common/managers/ReplyManager.ets:296-419`, `entry/src/main/ets/common/components/ReplyDialog.ets:17-173`).
- Critical state-isolation bug: normal `startThreadReply`, `startFloorReply`, and `startComment` do not clear cached post auth or pending attachment strings. Only `startEdit` and the never-called `reset` do. `getOrFetchAuth` reuses any cached successful auth without checking fid/tid/action (`entry/src/main/ets/common/managers/ReplyManager.ets:148-197`, `entry/src/main/ets/common/managers/ReplyManager.ets:246-259`). Attachment metadata/auth can leak into later dialogs, threads, or accounts, and stale auth can be reused against the wrong target.
- Send failures resolve normally in the page handler, but `ReplyDialog` clears the draft and closes whenever `onSend` resolves, regardless of `PostReplyResult.ok` (`entry/src/main/ets/common/components/ReplyDialog.ets:143-160`, `entry/src/main/ets/pages/ThreadPanel.ets:464-493`). Users lose the dialog/draft on a server-declared failure.
- “Compression” is a stub that returns the original bytes (`entry/src/main/ets/common/managers/ReplyManager.ets:262-265`). The picker reads the complete selected image into memory with no size limit, then upload always labels it `image/jpeg` regardless of actual format (`entry/src/main/ets/common/components/ReplyDialog.ets:100-140`, `entry/src/main/ets/service/NgaClient.ets:648-652`). This is image upload, not general attachment handling.
- Upload constructs multipart manually with an unescaped filename, hard-coded `origin_domain`, hard-coded image MIME, no shared throttling, and no client-side size/type validation (`entry/src/main/ets/service/NgaClient.ets:620-689`). The response parser globally changes every apostrophe to a quote and heuristically quotes keys, so legitimate apostrophes inside values can corrupt parsing (`entry/src/main/ets/service/api/ThreadApi.ets:441-476`).

### Tests and confidence

- The checked-in unit and device tests are default template assertions only; none exercise auth, codecs, failover, BBCode, pagination, favorites, or posting (`entry/src/test/LocalUnit.test.ets:1-33`, `entry/src/ohosTest/ets/test/Ability.test.ets:1-35`). README/wiki claims are therefore not backed by automated regression coverage in this snapshot.

## Caveats / Not Found

- This was static source inspection; no HarmonyOS device, NGA account, live endpoints, or DevEco build environment was used. Server response quirks, WebCookieManager flags, backup inclusion, and accepted URI schemes need device/network experiments.
- No git command was run. Snapshot identity was read directly from `.git/HEAD` and `.git/refs/heads/main`.
- Source search found no favorite-board drag/reorder implementation, no caller for `rotateDomain`, no caller for `setDomain`, no application of persisted `domainIndex`, and no call to `replyManager.reset`.
- Do not treat wiki line references as proof of behavior when they conflict with the source; the wiki accurately describes much of the architecture but frequently states intended/completed semantics more strongly than the code guarantees.

# 图片域名自动模式与服务端图床解析

## Goal

在现有「图片域名」手动选择能力上增加默认的「自动」模式：帖子详情优先使用
`THREAD.PAGE` 返回的 `data.__GLOBAL._ATTACH_BASE_VIEW`，让 NGA 再次迁移附件图床时不必依赖客户端发版；
同时保留现有两个预设、自定义覆盖、历史旧域名归一化，以及服务端字段不可用时的固定安全兜底。

## Background

- 当前 fork 已由 `NgaImageHost` 统一管理附件地址、手动预设、自定义值与历史图床归一化
  （`lib_base_common/.../NgaImageHost.java:25-163`）。
- 当前「图片域名」只有三个选项，存储值依次为 `0/1/2`，默认值为 `0`
  （`lib_base_common/src/main/res/values/arrays.xml:32-43`、
  `nga_phone_base_3.0/src/main/res/xml/settings.xml:14-20`）。
- 上游提交 `8862cdd498c2fb8c131e7a4082baef61ee09285c` 证明 `THREAD.PAGE` 的
  `data.__GLOBAL._ATTACH_BASE_VIEW` 可用于页面附件主机选择，但该提交只接入正文相对图片链，且存在以下缺口：
  `__GLOBAL` 空值未防护、协议写死为 HTTP、服务端值只按 `/` 粗切、附件区/投票/音视频/评论/签名/短消息未统一接入，
  历史绝对旧域名与非附件路径族也没有处理。
- `ArticleConvertFactory` 当前在解析 `THREAD.PAGE` 后直接构建每一行 HTML，但没有读取 `__GLOBAL`
  （`nga_phone_base_3.0/.../ArticleConvertFactory.java:59-69,91-139`）。
- 帖子正文、评论、签名和附件共享同一个 `HtmlData` 渲染上下文；短消息和若干旧入口没有
  `THREAD.PAGE.__GLOBAL` 上下文，自动模式必须使用固定安全地址，手动模式仍可正常覆盖。

## Requirements

### R1 图片域名选项与顺序

「图片域名」选择页必须且只能显示四个互斥选项，顺序固定为：

1. `自动`
2. `https://img.nga.cn`
3. `http://img9.nga.cn`
4. 现有自定义输入选项

新安装、缺失偏好值或偏好值损坏时默认选中 `自动`。自定义输入框现有的交互与校验保持不变：输入框常开，
点击或聚焦即选中自定义；非法非空值当场报错且不关闭对话框；空值运行期回退安全默认地址。

### R2 存储兼容

- 新存储值与 UI 顺序一致：`0 = 自动`、`1 = https://img.nga.cn`、
  `2 = http://img9.nga.cn`、`3 = 自定义`。
- 设置 XML、运行期缺省值和损坏值兜底统一改为 `0`。
- 升级时执行一次性迁移：旧值 `0` 保持为 `0`，使原默认用户自动切到「自动」；旧值 `1` 迁为新值 `2`，
  继续表示 img9；旧值 `2` 迁为新值 `3`，继续表示自定义并保留原输入内容。
- 迁移必须带独立 schema/完成标记，只执行一次；不得在每次启动时重复给值加一。

### R3 自动模式

- 仅在 `自动` 模式下，帖子详情解析必须读取当前 `THREAD.PAGE` 响应中的
  `data.__GLOBAL._ATTACH_BASE_VIEW`。
- 服务端值应按附件地址输入进行防御性解析，最终得到完整的页面级前缀，例如
  `https://img.nga.cn/attachments`。
- 服务端值缺失、空白、类型不符、协议不支持或格式非法时，自动模式统一回退
  `https://img.nga.cn/attachments`。
- 兜底只针对当前页面或当前无上下文调用，不得借用其他页面曾返回的结果；任何情况下都不得生成
  `null/...`、`http://null/...` 等坏 URL。
- 服务端结果只属于当前页面，不得写入偏好设置，也不得放进跨页面的静态缓存。

### R4 手动模式覆盖

- 选择 `https://img.nga.cn`、`http://img9.nga.cn` 或自定义时，必须忽略
  `_ATTACH_BASE_VIEW`，继续以用户所选地址为准。
- `http://img9.nga.cn` 必须保留 HTTP；不得为了统一协议改成 HTTPS。
- 修改「图片域名」不得影响既有「NGA 域名」设置，反之亦然。

### R5 页面级覆盖范围

同一个 `THREAD.PAGE` 解析出的完整附件前缀必须贯穿该页面的所有帖子行及嵌套评论，并覆盖：

- 正文相对 `[img]./...[/img]`；
- 正文中的音频/视频标签；
- 投票或评分内容中的相对图片；
- 附件区图片、音频与视频；
- 评论与签名中再次进入解码链的相对附件地址；
- 图片 URL 收集与大图浏览所使用的最终地址。

短消息、旧缓存兼容入口、独立签名/个人资料渲染和其他拿不到 `__GLOBAL` 的路径继续使用
`NgaImageHost` 的无上下文结果：手动模式尊重用户选择，自动模式使用固定安全前缀。

### R6 历史地址与路径族兼容

- 现有 `img*.nga.178.com` / `img*.ngacn.cc` 历史绝对地址归一化必须保留。
- 历史 `/attachments/` 地址在帖子页内应归一到该页最终附件前缀；路径、查询串与画质后缀保持不变。
- 非 `/attachments/` 路径继续保留原主机编号并只切换到 `.nga.cn`，不得把表情等资源错误压到附件主机。
- `ApiConstants` 中通过 Glide 直接加载的 `img4.nga.cn` 板块图标地址保持不变。

## Constraints

- 不照搬上游提交；只采用“服务端结果是页面级附件地址来源”这一核心机制。
- 不改 `references/` 下的固定上游参考源码。
- 不引入新的第三方依赖。
- 不更改附件上传主机、头像主机、NGA 主站域名或板块图标路径。
- 图片由 WebView/Glide 发起请求，方案不能依赖 Retrofit/OkHttp 图片拦截。
- 自动化验证只使用本地 fixture、单测、编译、lint 与静态扫描；没有新的明确授权时不访问 NGA、不运行 ADB/设备操作。

## Acceptance Criteria

- [ ] AC1 「图片域名」弹窗恰有四个互斥选项，顺序为
      `自动` / `https://img.nga.cn` / `http://img9.nga.cn` / 自定义输入项。
- [ ] AC2 新安装、缺失或损坏的图片域名偏好默认显示并使用 `自动`；`settings.xml` 默认值为 `0`。
- [ ] AC3 首次升级迁移后：旧 `0` 变为自动，旧 `1` 仍表现为 img9，旧 `2` 仍表现为自定义且输入值不丢失；
      后续启动不重复迁移。
- [ ] AC4 自动模式遇到合法 `_ATTACH_BASE_VIEW` 时，帖子正文相对图、投票图、音视频、附件、评论和签名
      全部使用同一个页面级附件前缀。
- [ ] AC5 自动模式遇到缺失、空白或非法 `_ATTACH_BASE_VIEW` 时，页面仍成功解析，并统一使用
      `https://img.nga.cn/attachments`；生成结果中没有 `null` 主机或其他合成坏 URL。
- [ ] AC6 三个手动模式均忽略服务端字段；img9 继续使用 HTTP，自定义地址继续执行现有归一化与错误提示。
- [ ] AC7 页面 A 与页面 B 返回不同服务端值时，各自只使用自己的结果，不发生跨页面串值或静态缓存污染。
- [ ] AC8 短消息及其他没有 `__GLOBAL` 的渲染入口不崩溃：自动模式使用固定安全前缀，手动模式使用所选地址。
- [ ] AC9 历史 `img*.nga.178.com` / `img*.ngacn.cc` 附件 URL 在帖子页内归一到页面最终前缀；
      非附件路径仍按原编号迁移到 `.nga.cn`，查询串和画质后缀不丢失。
- [ ] AC10 板块 fid/stid 图标仍使用现有 `img4.nga.cn` 常量，不被自动附件主机覆盖。
- [ ] AC11 修改「图片域名」与「NGA 域名」互不影响；设置主界面仍只增加原有的一行「图片域名」。
- [ ] AC12 聚焦单测、app Debug 编译及相关模块 lint/静态检查通过；仓库既有无关基线单独记录，不以放宽测试掩盖。

## Out of Scope

- 图片请求失败后的运行时探测、轮询或自动切换备用图床。
- 向服务端回写、持久化或跨页面复用 `_ATTACH_BASE_VIEW`。
- 重新设计图片缓存、预加载、画质、上传或 Cookie 策略。
- 对 `THREAD.PAGE` 之外的接口追加未经证实的 `__GLOBAL` 解析。
- 真机、模拟器、ADB 或新的线上 NGA 探测。

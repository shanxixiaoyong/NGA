# 板块与主题页 FAB 及主题刷新入口

## Goal

让板块页和主题页的悬浮操作按钮始终稳定承担各自的主要创作动作，并在主题页右上角更多菜单的第一项提供明确的当前页刷新入口。

## Background

- 板块页与主题页当前都通过 `ScrollAwareFabBehavior` 在向下滚动时隐藏 FAB、向上滚动时重新显示。
- 用户已正式决定不让 FAB 随滚动消失或改变功能：板块页固定发帖，主题页固定回复。
- 主题页已有下拉刷新，但右上角更多菜单目前没有刷新入口。
- 当前页码被再次点击时只回到该页顶部，本次不改变这一行为。

## Confirmed Repository Facts

- 板块 FAB 直接调用发帖流程（`TopicListFragment.java:94-103`），主题 FAB 直接调用回帖流程（`ArticleTabFragment.java:131-145`）。
- 两个布局都通过 `app:layout_behavior="sp.phone.view.behavior.ScrollAwareFabBehavior"` 控制滚动隐藏（`fragment_topic_list_board.xml:47-56`、`fragment_article_tab.xml:43-52`）。
- 主题页更多菜单由 `article_list_option_menu.xml` 定义，并在 `ArticleTabFragment.onOptionsItemSelected()` 中处理；当前没有刷新菜单项（`ArticleTabFragment.java:147-183,225-227`）。
- 当前主题页刷新入口最终调用 `ArticleListFragment.loadPage()`；本次只复用该既有路径，不改变 Presenter、Model、账号 Cookie、WebView fallback、错误处理或滚动恢复机制。
- 主题缓存页使用同一外层布局，但会明确隐藏回复 FAB（`ArticleCacheActivity.java:49-55`）。

## Requirements

- R1. 板块页 FAB 始终可见并始终只负责“发帖”；不随滚动隐藏，不随滚动方向改变图标、文案或点击功能。
- R2. 主题页 FAB 始终可见并始终只负责“回复”；不随滚动隐藏，不随滚动方向改变图标、文案或点击功能。缓存主题页继续隐藏该 FAB。
- R3. 仅主题页的楼层列表保留略大于回复 FAB 实际遮挡范围的底部安全留白，使每页最后一层的操作区能够滚动到 FAB 上方。板块主题列表不增加尾部留白。
- R4. 在主题页右上角更多菜单增加菜单项，显示名称严格为“刷新”，并排列为菜单的第一项。
- R5. 点击“刷新”只调用当前分页既有的 `loadPage()` 刷新路径；不回到顶部、不切换分页、不触发回帖，并在已有刷新进行时避免重复发起请求。
- R6. 当前页码再次点击仍只回到当前页顶部，不增加刷新、长按或二次点击语义。

## Acceptance Criteria

- [ ] 板块页首次进入、向下浏览和向上返回时，FAB 都保持可见、保持发帖图标与“发帖”无障碍文案，点击只打开发帖。
- [ ] 主题页首次进入、向下浏览和向上返回时，FAB 都保持可见、保持回复图标与“回帖”无障碍文案，点击只打开回帖；缓存主题页仍不显示 FAB。
- [ ] 主题每个分页的最后一层可以滚动到回复 FAB 上方；留白不是楼层、不参与楼层数或页码计算。板块列表没有新增尾部留白。
- [ ] 主题页更多菜单的第一项显示为“刷新”，点击后只刷新当前分页，并复用现有主题页加载流程。
- [ ] 下拉刷新、当前页码点按回顶、发帖和回帖功能保持可用。
- [ ] 本次产品代码 diff 不包含刷新失败保护、账号切换策略、WebView fallback、页面关闭策略、`pid + 像素偏移` 恢复、贴条/评论同步、设置项或自动吞楼恢复的改动。

## Out of Scope

- 刷新失败时保留旧内容或阅读位置。
- 禁止刷新失败后的下一账号 Cookie 重试、WebView fallback 或原生页面关闭。
- 成功刷新后的 `pid + 像素偏移` 阅读位置恢复。
- 修改“回帖后刷新内容”设置。
- 修改贴条/评论成功后的刷新或局部同步行为。
- 自动吞楼检测、定期刷新及其实验室开关。
- 板块页刷新菜单、板块页尾部安全留白或动态 FAB 功能切换。

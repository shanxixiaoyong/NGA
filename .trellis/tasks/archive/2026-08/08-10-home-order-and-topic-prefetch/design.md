# 首页排序与主题预读取优化：集成设计

## Task Boundary

父任务不直接承载产品代码。两个子任务分别拥有首页栏次顺序与主题页预读取的实现、测试和回滚点；父任务只维护统一需求、子任务映射和最终集成检查。

## Cross-Child Architecture

```text
首页栏次数据与 Compose Pager
  -> 稳定 ID 顺序覆盖层
  -> 长按拖动与偏好持久化

THREAD.PAGE 当前页响应
  -> __ROWS / 20 得到总页数
  -> 后两页规划器（严格排除末页）
  -> 当前 Article Activity 内的离屏 Fragment 预读取
```

两条数据流没有共享状态或文件。共同约束只有：保持现有导航/视觉基线、使用纯逻辑测试固定边界、不执行未授权设备操作或真实 NGA 验证。

## Integration Contracts

- 收藏板块仍为首页 Pager 第 0 页；新的第 1 页为网事杂谈。现有首页侧栏合同中把“收藏板块后相邻页”的名称从魔兽世界更新为网事杂谈，但手势方向和阈值不变。
- `TabLayoutWithPager` 的排序扩展必须保持默认参数可选，非首页调用方继续获得原行为。
- `THREAD.PAGE` 继续使用现有 Retrofit、Cookie、解析器和前台重试链；预读取只增加静默调度，不改变 wire contract。
- 两个子任务都不得借机重构无关的收藏、网络、缓存或页面架构。

## Delivery And Rollback

1. 先完成并检查首页栏次子任务，确保首页默认/自定义顺序与既有侧栏/收藏手势同时通过。
2. 再完成并检查主题预读取子任务，确保末页排除和前台失败回退通过。
3. 最后运行应用级构建、单元测试、lint 报告检查和仓库诊断基线。

任一子任务失败可独立回滚：首页回退到固定 asset 顺序和无标签拖动；预读取回退到当前仅 RESUMED 页加载。两个回滚均不需要迁移用户内容或服务端数据。

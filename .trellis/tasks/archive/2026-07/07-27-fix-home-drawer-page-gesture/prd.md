# 修正首页侧栏为相邻页手势

## Goal

将首页的水平空间表现为“侧栏｜我的收藏｜魔兽世界｜其他版面”：用户在“我的收藏”上向侧栏方向翻页时可从页面任意水平位置拖出侧栏，向反方向翻页仍进入“魔兽世界”。

## Background

- 首页版面数据顺序是“我的收藏”后紧接“魔兽世界”：`ForumBoardRepository.loadBookmarkBoardList()` 会在 `board_list.json` 的“魔兽世界”之前添加收藏页。
- 从“我的收藏”向右侧相邻页翻动并进入“魔兽世界”的交互已正常实现，本任务不改写或替换该路径。
- 当前只有“我的收藏”向左侧相邻页翻动是无功能的边界手势；本任务将该无功能方向连接到侧栏。
- 上一版实现将侧栏限定为 24dp 左边缘手势，这与用户期望的“相邻页”模型不符。
- `ModalNavigationDrawer` 和内层 `HorizontalPager` 共享水平手势，需要按当前分页和手势方向仲裁。

## Requirements

- R1. 侧栏在水平导航中视为“我的收藏”左侧的相邻页，不是屏幕边缘快捷操作。
- R2. 当“我的收藏”已稳定停靠时，从页面任意水平起点向左侧相邻页翻动（内容跟随手指向右移动）应连续拖出现有侧栏。
- R3. 当“我的收藏”已稳定停靠时，保留已有的向右侧相邻页翻动路径（内容跟随手指向左移动），继续进入“魔兽世界”。
- R4. 在“魔兽世界”或更后面的版面页上，水平手势应按页面顺序逐页移动；不得跳过“我的收藏”直接打开侧栏。
- R5. 删除 24dp 边缘命中、边缘宽度常量和为该方案添加的 `systemGestureExclusion`。
- R6. 保留左上角三横线菜单图标，点击仍打开同一侧栏；子页仍默认使用返回箭头。
- R7. 收藏项长按拖拽排序激活后，排序独占该手势，不打开侧栏也不切换分页。
- R8. 侧栏的松手回弹、向关闭方向拖动及点击遮罩关闭行为保持不变。
- R9. 侧栏手势实现必须使用公开 Compose API 和单一共享拖动状态，不依赖 Material3 内部成员、反射或竞态式重组门控。

## Acceptance Criteria

- [ ] AC1 (R1, R2, R5): 在“我的收藏”内从左侧、中间或右侧起手，向左侧相邻页翻动都能连续拖出侧栏，不存在 24dp 起手限制。
- [ ] AC2 (R3): 在“我的收藏”执行现有右滑后仍显示“魔兽世界”，手势阈值、动画和分页结果不变，且不打开侧栏。
- [ ] AC3 (R4): 在“魔兽世界”向收藏页方向翻动时先回到“我的收藏”，再执行一次同方向手势才打开侧栏。
- [ ] AC4 (R5): 代码中不再存在本功能的 `DrawerEdgeWidth`、`isWithinDrawerEdge` 或 `systemGestureExclusion`。
- [ ] AC5 (R6): 左上角三横线按钮仍可打开侧栏，其辅助功能描述仍为“打开侧边栏”，其他页面的返回图标不变。
- [ ] AC6 (R7): 长按收藏项并拖动只改变收藏顺序，不触发侧栏或分页。
- [ ] AC7 (R8): 侧栏开启后的拖动关闭、回弹和遮罩点击关闭行为不变。
- [ ] AC8: 方向仲裁、分页边界和菜单图标有自动化覆盖，受影响 Android 模块的编译、单测和 lint 通过。
- [ ] AC9 (R8, R9): 侧栏使用关闭/打开两个锚点，按 Material 对等的 50% 位置阈值、400dp/s 速度阈值和 256ms 动画结算；取消手势回到原稳定锚点。

## Out of Scope

- 不改变侧栏内容、宽度、色彩或用户信息布局。
- 不改变版面数据顺序、收藏数据或排序持久化。
- 不把侧栏改造为 `HorizontalPager` 中的普通全屏页。
- 不通用化或替换项目其他页面的抽屉容器；新容器仅服务首页这一个方向仲裁场景。

## Key Decisions

- 手势方向以“目标相邻页”描述，同时在括号中记录内容跟手方向，避免再次混淆手指方向和页面方向。
- 只有已稳定停靠的第一页才能把向左侧相邻页的手势交给侧栏。
- Material3 1.3.2 的 `DrawerState` 不公开增量拖动和结算接口；为了消除首帧大位移竞态，首页使用 Foundation 1.7.0 公开 `AnchoredDraggableState` 的专用容器，并复用 Material `ModalDrawerSheet` 内容。
- 该修正涉及同向嵌套手势仲裁和收藏排序互斥，使用 PRD + design + implement 的完整规划。

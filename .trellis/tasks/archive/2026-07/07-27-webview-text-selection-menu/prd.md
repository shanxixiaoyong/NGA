# 自定义文本选择菜单

## Goal

让用户在帖子详情中长按并选中原生正文时，只看到常用的“复制、全选、搜索”三项操作，去掉不需要的文本分享入口，并能把选中文字交给系统网页搜索。

## Background

- 帖子详情的原生正文由 `fragment_article_list_item.xml` 中的 `tv_content` 渲染，并显式启用了 `android:textIsSelectable="true"`。
- `ArticleListAdapter` 在楼层没有格式化 HTML 时使用该 `TextView`；格式化 HTML 使用的 `LocalWebView` 当前禁用了长按，不属于本次可选文本菜单范围。
- 其余已检索到的普通文本控件未显式开启文本选择，或明确设置为不可选择。

## Requirements

- R1. 原生帖子正文的文本选择浮动菜单必须按“复制、全选、搜索”的顺序呈现，且不再呈现“分享”或其他系统/第三方文本处理项。
- R2. “复制”和“全选”继续使用 Android `TextView` 的原生文本操作语义，包括选择范围和剪贴板行为。
- R3. 点击“搜索”时，以当前非空选中文本作为 `SearchManager.QUERY`，通过 `Intent.ACTION_WEB_SEARCH` 交给系统的网页搜索处理程序，并结束当前文本选择操作模式。
- R4. 选区无效、选中文本为空或设备没有可处理网页搜索 Intent 的应用时，不得导致应用崩溃。
- R5. 改动仅作用于帖子详情的原生正文 `tv_content`，不得改变文本输入框、帖子级分享功能、图片分享功能、个人资料 WebView 或内置网页页的行为。
- R6. 保持现有 Android 11 至 Android 15 支持范围，不新增第三方依赖。

## Acceptance Criteria

- [x] 长按并选中原生帖子正文后，浮动菜单仅包含“复制”“全选”“搜索”，顺序一致，且没有“分享”。
- [x] 点击“复制”后，选中文字进入系统剪贴板；点击“全选”后，当前正文全部被选中。
- [x] 点击“搜索”后，系统网页搜索处理程序收到准确的选中文本并在应用外打开。
- [x] 无有效选区、纯空白选区或没有网页搜索处理程序时，应用保持稳定。
- [x] 格式化正文 WebView 的既有长按设置和应用内其他分享入口保持不变。
- [x] `nga_phone_base_3.0` 的相关单元测试和编译检查通过。

## Out Of Scope

- 为格式化正文 `LocalWebView` 或内置网页页新增文本选择能力。
- 在应用内实现独立搜索结果页或指定固定搜索引擎。
- 修改帖子、图片、日志等现有显式分享功能。
- 定制系统选择手柄、浮动工具栏外观或厂商系统动画。

## Technical Notes

- 使用 `TextView.setCustomSelectionActionModeCallback` 定制原生正文菜单；自定义回调消费“搜索”，让 `TextView` 继续处理系统的复制和全选 action id。
- 实现与界面绑定应保持局部，避免改变共享 WebView 基类或全局文本输入行为。

# 默认跳过 ADB 真机测试

## Goal

将维护者关于设备测试的长期偏好写入 Android 质量规范，避免后续任务主动探测
ADB、要求连接真机，或把未运行真机测试当作交付阻塞项。

默认验证继续使用不依赖设备的构建、单元测试、静态检查和可离线执行的测试；只有
维护者在具体任务或当前对话中明确要求时，才执行 ADB 设备操作或真机测试。

## Background

- 当前 `.trellis/spec/backend/android-quality-guidelines.md` 允许在设备可用时运行
  `connectedDebugAndroidTest`，仍可能促使后续执行者主动检查 ADB 或等待设备。
- 维护者通常没有时间连接真机，并明确要求从默认流程中移除该步骤。
- 现有 ADB 传输、安装和 instrumentation 诊断规则仍有参考价值，但只应在维护者
  明确启用设备测试后生效。

## Requirements

- 在 Android 质量规范中增加优先级明确的默认设备测试策略。
- 未收到当前任务中的明确要求时，不运行 `adb`、`adb.exe`、
  `connected*AndroidTest`、设备安装、设备 shell、logcat、端口转发或真机 E2E。
- 不主动执行 `adb devices` 或等待维护者连接设备；设备碰巧在线也不构成授权。
- 允许默认编译 `androidTest` 源码或测试 APK，但不得安装或在设备上执行。
- 未授权的设备测试应在验证结果中标记为按项目策略未运行，而不是失败、阻塞或待
  维护者补测；不得要求维护者自行完成该步骤后才能交付。
- 设备无关的构建、JVM 单元测试、lint、静态检查和离线验证仍按现有规范执行。
- 当维护者明确要求设备测试时，继续遵循现有精确 serial、Windows ADB、无真实 NGA
  流量和安全限制；该授权只适用于明确指定的任务或操作，不改变未来默认值。

## Out of Scope

- 删除 instrumentation 测试源码、runner 配置或设备诊断文档。
- 降低设备无关的构建、单元测试、lint 或静态检查要求。
- 本任务实际连接、查询或操作任何 Android 设备。
- 批量重写历史报告或已归档任务；全局规范负责约束后续执行。

## Acceptance Criteria

- [x] Android 质量规范明确说明：ADB 和真机测试默认不运行，只有维护者在当前任务中
      明确要求才可运行。
- [x] 规范明确说明：不得为了判断可用性而主动查询 ADB，设备在线本身也不是授权。
- [x] 规范列出默认跳过的设备操作，并区分“可编译设备测试产物”和“不可默认安装/
      执行”。
- [x] 规范明确说明：默认未运行的设备测试不阻塞交付，也不转化为维护者待办。
- [x] 规范保留显式授权后的 Windows ADB、精确 serial、安全和报告要求。
- [x] 文档检查确认新的默认策略与原有“设备可用时运行”措辞不再冲突。

## Notes

- 这是轻量规范任务，PRD-only 足够；不需要 `design.md` 或 `implement.md`。

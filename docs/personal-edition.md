# NGA 个人增强版功能与使用说明

本文记录 `5.5.0-personal.35` 相较于上游 NGA Just Works/原始 Justwen
客户端的用户可见变化。此版本仍是非官方第三方客户端，与 NGA、LINUX
DO 及相关项目不存在隶属、授权或背书关系。

## 1. 品牌与默认外观

- 应用显示名称由 `NGA Just Works` 简化为 `NGA`。
- 默认使用绿色 Material 主题、浅色模式和纯色列表背景。
- 首页顶部栏与内容之间取消阴影和额外间隔，保持纯色连续视觉。
- 新安装默认尺寸依次为：主题标题 `18sp`、头像 `104px`、表情
  `60px`、正文 WebView 缩放 `70%`。
- 已安装用户原有的手动设置继续保留；上述值主要是新安装或重置后的
  默认值。

## 2. 首页与导航

- 收藏板块固定在首页第一栏，不再新增或保留“推荐”聚合页。
- 首页其他板块标签支持长按拖动排序，顺序跨账号保存。
- 收藏板块卡片支持长按直接拖动排序。
- 收藏页可从内容区域连续跟手滑出侧边栏；保留普通左右翻页手势，避免
  与列表滚动和排序互相抢手势。
- 为标签和收藏板块排序提供 TalkBack 移动操作。
- 首页与列表恢复轻松有趣的随机加载语，进度动画与当前绿色主题协调。

## 3. 所有普通板块的主题列表

- 主题列表第一行继续显示标题；第二行左侧由发帖人改为所属板块，右侧
  由最新回复人改为“最新回复距现在多久”，原有回复数继续显示。
- 已打开过的主题标题显示为灰色。
- 已读主题出现新回复时，在完整标题末尾显示醒目的绿色圆点；多行标题
  的圆点跟随最后一行文本，而不是固定悬在控件最右侧。
- 已经完全读完且没有新回复的主题从列表投影中隐藏，减少反复刷新时的
  已读内容占位；出现新回复后会重新显示。
- 长按主题弹出紧凑、对称的一行双按钮：`屏蔽帖子`、`屏蔽板块`。
- 屏蔽后使用 RecyclerView 原生移除/补位动画，不重建整页。
- 设置页新增已屏蔽板块管理，可查看并取消屏蔽；帖子和板块状态按数据源
  隔离，避免 NGA 与 LINUX DO 的数字 ID 冲突。
- 沿用普通板块原有下拉刷新和 RecyclerView 惯性滚动，不引入独立推荐流
  或自制刷新控件。
- 点击列表顶部标题会回到顶部并刷新第一页；正在加载时不会重复请求。

## 4. 帖子阅读与进度

- 阅读进度记录到真实服务器楼层，而不是列表位置；离开页面前会记录已
  经完整暴露过的最高楼层。
- 再次打开灰色主题时自动进入上次阅读位置，并把第一条未读楼层放在
  屏幕顶部。
- 已读与未读楼层原有分割线上显示“已定位到上次阅读位置”，不会额外
  插入第二条线或虚构楼层。
- 不再折叠已读楼层，也不保留额外的跳转按钮；回复按钮维持原版右下角
  大小和位置。
- 去除帖子页末尾为回复按钮预留的永久 `80dp` 空白，最后一楼结束后只
  保留正常行距和系统安全区。
- 到达当前页底部后，再继续直接向上拖动并超过阈值，可切换到下一页；
  普通滚动、惯性滑到页底、短拖、反向拖动和最后一页不会误触。
- 保留原有横向左滑翻页，并静默预取当前页之后最多两页；末页不预取，
  以便真正打开时获取最新回复。
- 当前页签可长按刷新：立即刷新一次，继续按住时每五秒刷新，松开停止；
  短按仍只回到顶部。
- 楼层元数据恢复原版“级别 / 威望 / 发帖”布局，不再实时请求属地，避免
  NGA 资料接口的频率限制影响阅读。
- 发帖与回复按钮保持常驻，不再随滚动隐藏。

## 5. NGA 接口异常与网页恢复

- NGA 原生接口返回完整 JSON 时继续走原来的轻量快速路径；对于数字字符串、
  缺失计数和可选字段形状变化做防御性解析。
- NGA 随机只返回 JSON 前半段时不再猜测或补全缺失正文，而是请求同一帖子
  的服务端网页，把网页中已经完整渲染的楼层转换为原生阅读器数据。
- 对 `data`、主题、回复、用户、评论和数字字段先检查形状，坏掉的可选
  字段尽量跳过，避免单个异常楼层让整个帖子崩溃。
- 网页恢复仍失败时才进入同一帖子的浏览器模式；恢复过程串行、有超时且
  用完即销毁，不会形成重试循环或常驻 WebView。
- 失败诊断保持脱敏，不包含正文、Cookie 或登录信息。
- 保留传统 NGA 客户端身份请求头，避免服务端因客户端身份缺失返回异常。

## 6. 图片、附件与正文交互

- 图片域名支持“自动”、两个官方域名和自定义 HTTPS 域名；自动模式按
  当前页面返回的图床地址处理正文、评论、签名、投票、音视频和附件。
- 重写历史正文中已经写死的旧图床地址，恢复图片、板块图标、附件、投票
  配图、音视频和看大图。
- LINUX DO 正文图片和视频限制在正文宽度内并保持原始宽高比，修复图片
  拉伸；正文左右保留 `8px` 内边距，并清理每层楼末尾的重复空白。
- 帖子正文长按选词菜单由应用接管，只保留“复制”“全选”“搜索”，移除
  “分享”和第三方应用注入项。

## 7. LINUX DO 原生板块

- 收藏板块首次迁移时新增一个 `LINUX DO` 默认入口；只添加一次，不覆盖
  用户已有顺序，也不会在用户主动删除后反复添加。
- 点击后直接进入 NGA 风格的原生主题列表，不把网页登录页当作日常前端。
- 侧边栏可登录 LINUX DO 账号，原生列表随登录态读取账号可见的主题；只有
  首次登录、会话失效或 Cloudflare 验证时才显示网页登录界面。
- 原生列表显示标题、分类、标签、最新回复相对时间、回复数、已读灰色状态、
  新回复绿点，并支持关注、帖子屏蔽和分类屏蔽。
- 原生阅读器映射楼层、作者、头像、时间、分类、回复数、点赞数、信任级别、
  徽章和头衔；大帖按 Discourse `post_stream` 分页补取。
- 支持普通楼层与简短 Boost 回复。每楼的快速回复按钮默认直接针对该楼发起
  Boost；“更多”菜单仍可明确选择普通回复或 Boost 回复。
- 已登录用户可在原生阅读器内回复、Boost 和点赞；操作使用 LINUX DO 独立
  会话，不会误发到 NGA。点踩、发帖、上传等操作仍未接入。
- LINUX DO 分享和“浏览器打开”使用正确的 `linux.do/t/{id}` 地址。
- Cookie 只在 LINUX DO 同源会话中使用，不复制 NGA Cookie，也不把正文、
  Cookie 或登录信息写入日志。

## 8. LINUX DO 专用网络通道

- 设置页“域名与账号”提供独立的 LINUX DO DoH 地址，默认值为
  `https://cloudflare-dns.com/dns-query`；修改后只影响 LINUX DO，NGA
  请求完全不变。
- 已知 Cloudflare/阿里 DoH 使用预置引导地址连接，避免解析 DoH 域名时
  再次依赖已被污染的系统 DNS；自定义 DoH 保留系统引导。
- Android 14 及以上使用系统 Chromium `HttpEngine` 查询 Cloudflare，
  再把得到的数字地址映射给 Google Play services Cronet，并强制以 QUIC
  请求 LINUX DO JSON。该路径解决“DNS 已正确解析，但普通 TCP/TLS 仍被
  重置”的网络环境。
- LINUX DO 用户头像与行内 Boost 小头像也经过同一独立 DNS/QUIC 通道，
  并使用有界缓存和并发合并，避免系统 DNS 被污染时正文能开而头像空白。
- 网络组件按需创建、限制单执行器、20 秒超时、DNS 响应最大 64 KiB、
  帖子响应最大 8 MiB；没有内置完整 Chromium、Flutter、后台轮询服务、
  本地代理或用户 CA。
- 其他 DoH 地址及较旧 Android 版本使用轻量 OkHttp DoH 路径；如果当地
  网络同时封锁普通 TLS/SNI，旧系统上仍可能需要系统代理。

## 9. 其他长期增强

- 表情面板支持分类内长按拖动排序，并可在设置中重置。
- 发帖/回复工具栏调整为“主题分类、排版、图片、表情”，移除键盘按钮。
- 应用使用 open-nga 风格的自适应图标。
- 恢复 Android 10（API 29）安装支持，同时保持 targetSdk 35。
- Release 使用 R8 压缩、固定个人签名、正式应用 ID 和不可调试配置，可在
  同一个人签名版本之间直接覆盖升级。

## 10. 当前限制

- LINUX DO 已支持登录、普通回复、Boost 和点赞；发帖、点踩、收藏、通知、
  聊天和上传尚未接入。
- LINUX DO 是对公开 Discourse JSON 结构的兼容实现，并非官方稳定 API；
  论坛结构或 Cloudflare 策略变化后可能需要继续适配。
- 此版本是个人增强构建，签名与 GitHub 上游正式版不同。第一次从上游版
  切换时可能需要卸载原应用；安装过同一个人签名版本后可以覆盖升级。
